## Simple implementation using the existing pipeline

1. Reuse parsed passages, source IDs, BM25, cached biomedical embeddings and chat-provider adapters. Add one tool-free structured screening operation, not another autonomous agent or framework. Resolve the screener model from an optional `SCREENING_MODEL`, defaulting to `LLM_MODEL`, using the existing provider:model contract. Apply OpenRouter-only routing only to OpenRouter; never forward it to LiteLLM. Do not install or substitute an embedding model.
2. Construct paper-level inputs containing publication/version identity, title/abstract, and available introduction, methods, results, discussion, captions and supplement inventory. Preserve section/paragraph IDs and offsets. Source content is data, never instructions. Prefer the complete available main text when it fits the actual model/input budget; exclude bibliography/duplicated boilerplate with a recorded policy. Missing sections and parse failures must be declared.
3. For oversized papers, create section-aware windows with local overlap, reuse a common paper context header, and process ALL retained main-text windows before claiming full-text screening completion. BM25 plus dense retrieval orders relevant windows and retrieves adjacent/linked methods/captions; a global top-k must not silently discard the rest. Unread windows remain explicit. Merge structured results deterministically; include if any source-grounded window is relevant, retain uncertainty when context is missing, and never exclude an entire paper from one negative window. Avoid an extra summary/model call unless a specific unresolved cross-window decision requires it. Do not promise exactly one API call for every paper.
4. Do not dump numerical supplements into chat. Provide filenames, sheet/table labels, headers and bounded source-grounded previews for relevance triage. Retain table-analysis/parse blockers and route to existing deterministic table processing or the bounded evidence-assembly queue. Screening cannot infer an unstated comparison, run statistics or convert expression into regulation.
5. Return validated structured records: publication ID, source hashes, evaluated section/window IDs, missing/unread coverage, and per-manuscript-question decision (`include_for_extraction`, `background`, `needs_full_text_or_context`, `exclude_with_reason`). Include source-reported TFs/genes, species, tissue/cell context or unknown, primary/secondary attribution, evidence category (regulation, binding, motif, expression, computational prediction, background), cited passage IDs/exact spans, reason and unresolved needs. A model's confidence is not evidence. Validate that citations exist in the supplied input. Invalid outputs get bounded repair/retry, otherwise explicit failure/needs-review; never silent exclusion.
6. Allow nonhuman and name-only findings into relevance screening while retaining uncertainty. A human-ID annotation is not experimental species. Preserve negative/null findings. A paper may be background for one question and relevant to another; do not collapse it to a universal exclusion. Title/abstract hints prioritize, not veto. Screening produces candidate relevance decisions, not verified KG assertions.
7. Use selected passage IDs to rebuild source-grounded extraction candidates through existing serialization/readiness gates. The LLM cannot override missing assets, malformed tables, context limits or unresolved experiment linkage. Stage retrieval repair only for newly identified relevant evidence. Keep a source snapshot before screening; do not require final paper selection to be frozen before the screening that determines it. Freeze extraction inputs after screening/source-readiness reconciliation.
