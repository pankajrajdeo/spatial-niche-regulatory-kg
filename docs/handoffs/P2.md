Consequential decisions:

1. **P1 code is untouched.** P1's ingest key hashes `provenance.py`, `models.py`, `identifiers.py`, and `project_data/`. All P2 code therefore lives in new modules: P2 schemas are in `analysis/schemas.py` rather than `models.py`, and HGNC enrichment is in `analysis/gene_mapping.py` rather than `identifiers.py`.
   - Consequence: `regkg ingest` still returns `REUSED` for `ingest-6f3b10c688adf3b6`, re-run after P2.
   - Mappings enrich P1's `gene_id` (one row per P1 gene, in P1 order); no P1 identity changes.
2. **CollecTRI is parsed from the raw export, not through `decoupler.op.collectri()`.** Decoupler 2.2.0's wrapper downloads the same Zenodo file but then applies `dropna()`, which would drop the 185 records without references, and `drop_duplicates(["source","target"])`, which keeps the first of any contradictory pair. That conflicts with P2.3. The raw export URL is exactly the one decoupler 2.2.0 documents, and decoupler is still used for ULM (`decoupler.mt.ulm`, public API).
3. **Sign basis.** CollecTRI's `sign_decision` field takes three values:
   - `PMID`: literature-evidenced sign.
   - `regulon`: sign inferred from the TF's regulon majority.
   - `default activation`: no evidence; +1 assumed.

   This interpretation was confirmed in the lead review against the CollecTRI publication (Müller-Dott et al., NAR 2023). `default activation` records (21,730 of 43,175) are stored with `sign=unknown` and the raw weight kept.
   - **The primary ULM uses only `pmid_evidence` and `tf_regulon_majority` records** (policy **`literature_or_regulon_sign`**, a project analysis choice; regulon-inferred signs are not edge-specific experimental evidence). Candidates are selected from this policy.
   - A clearly labelled sensitivity policy, `sensitivity_collectri_assigned_weights`, reproduces standard CollecTRI usage including the assumed +1 weights. It is stored in `concordance.parquet` only.
4. **`ulm(..., empty=False)`.** Decoupler's default removes features whose value is 0, which here means genes with an exactly zero Niche2−Niche1 effect: 2,986 of the 21,880 genes in the first run's Control vector.
   - A zero difference is a supplied value, so the full vector is kept.
   - The stage cross-checks that decoupler's `tmin` filtering matches the recorded target coverage; this check caught the issue.
5. **Gene resolution rules** (P2.1, exact and case-sensitive):
   - Approved symbol first; otherwise resolve only when the union of previous-symbol and alias owners contains exactly one HGNC ID.
   - A symbol naming several IDs is `ambiguous`.
   - A non-exact mapping onto an HGNC ID already held by another supplied feature is `conflict_shared_hgnc_id`, with its HGNC ID nulled, so distinct features are never merged.
   - No case folding and no suffix stripping (`MATR3.1` stays unresolved).
6. **Candidate identity:** TF × comparison, keyed by HGNC ID. Ties on |ULM score| break by HGNC ID string. Complexes (AP1, NFKB) are never candidates.
7. **Queue priority** interleaves TFs: every TF's first query comes before any TF's second. Within each round, seeds come first, ordered by HGNC ID; manuscript order is not used.
   - Per TF, the sequence is: top assay query, the lung-context query, the remaining assay queries, then one null/negative-phrasing query.
   - Queries shared by Control and IPF are merged and keep both memberships.
   - The first 20 queries cover all 14 unique TFs.
8. **Safe aliases** (maximum 3 per gene): an alias qualifies only if it is unique across all HGNC symbol, previous, and alias fields, has at least 4 characters, and contains a digit. This excludes, for example, KLF5's `CKLF` (another gene's approved symbol) and short aliases like `AA`.
   - Lung-context terms omit bare "AT1", which also names the angiotensin II type 1 receptor.
   - No date restriction is applied.
9. **Removed my superseded, unreviewed dev artifact** `candidates-2071991df16ec388`. Its tables were byte-identical to the final one; the key differed only because of a later config and code change. Its execution record, and three FAILED development execution records, remain in `data/runs/`.

## Limitations and blockers

No blocker. Items for review:

1. **Sign-basis interpretation and the ULM policy** (decision 3). Excluding default-activation records halves the network and changes which regulators pass `tmin`, so selections differ from standard CollecTRI/decoupler usage. For example, the sensitivity policy ranks PLAGL2 and RXRG highly. Both results are stored; the lead review accepts the primary policy as an explicitly labelled project analysis choice.
2. **Concordance additions often rest on few targets:** MKX 6, TRPS1 7, WWTR1 8, NCOA2 and YAP1 9. `min_targets=5` is an engineering setting, not evidence strength.
3. **Candidates are individual-gene CollecTRI regulators, not necessarily DNA-binding TFs.** This is recorded in every candidate row (`regulator_scope`) and in the coverage notes. YAP1, WWTR1, and NCOA2 are generally described as co-regulators. Per the review, no TF census was added, and neither direct binding nor TF status is inferred from a CollecTRI entry or a high ULM score.
4. The HGNC "unresolved" group (12,408) is mostly clone-based lncRNA names. The 118 conflicts and 11 ambiguous symbols are excluded from ULM and target selection, with counts.
5. The query text is service-neutral boolean syntax; P3 must adapt it to PubMed or Europe PMC. Alias safety is heuristic and versioned (`p2-queue-1`).
6. No opposite-niche view, no other priors (TRRUST, hTFtarget, KnockTF), no embeddings, no literature calls, and no LLM or Neo4j work, all per scope.
7. No secrets were read or printed. `.env` was not touched.
