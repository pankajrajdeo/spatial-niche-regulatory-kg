Consequential decisions:

1. **Interpreter and lock.** uv 0.12.15 was already installed, so I used a uv-managed CPython 3.12.14 (`uv venv .venv --python 3.12 --seed`). No global shim or system Python was changed, and the system `python3` remains 3.14.7. Installs use `uv sync --locked --extra test --inexact`; `--inexact` keeps the seeded pip 26.2.1 that `pip check` needs. For P2, a no-install `uv pip compile` shows that `decoupler==2.2.0` resolves against the pinned pandas 3.0.6, numpy 2.5.3, and scipy 1.18.1. That is a metadata resolution only; runtime compatibility is P2's to verify.
2. **Identity split.**
   - `contexts.parquet` has one row per source column label.
   - `context_id` is the condition-specific biological context: dataset, species, tissue, cell type, condition, and model system, with no niche.
   - `niche_state_id` is nullable: dataset, definition run, focal cell type, and niche label, with no condition.
   - Observation IDs = source ID + gene ID(s) + context label + resolved context and niche (repair R2). A revised source file or assignment therefore gets new observation IDs rather than overwriting old ones.
   - `comparison_id` is semantic (dataset, cell type, condition, context, case/reference niche) and carries no source ID.
3. **Exact float preservation.** An independent verify re-read found that pandas' default C float converter stored 619,604 signature cells 1 ULP (≤4.4e-16) away from the correctly rounded source decimals. All readers now use `float_precision="round_trip"`. The verify re-read parses with Python `float()`, so it is independent of the ingest parser. After the fix, every value in every table is identical to its source.
4. **Artifact key.**
   - The key covers `ingest-` + SHA-256 of the stage, schema version, source role/hash, result-affecting config, and ingest code fingerprint.
   - `ingest_chunk_rows` and `data_root` are excluded. A different chunk size changes the Parquet row-group bytes but not table content (tested).
   - Git is present but the tree is dirty, so the code-file hash is the operative code identity; the commit and dirty flag are also recorded.
5. **Failures.** Duplicate semantic keys, duplicate headers, blank or NaN text in numeric columns, non-finite values, effect mismatches, out-of-range fractions, fractional or inconsistent cell counts, row sums ≠ k, filename/config disagreement, and niche labels outside the configured definitions all abort before publication. The error message names the problem, the staging directory is discarded, and a `FAILED` execution record is written. Nothing is dropped, averaged, or filled.
6. **Removed my own superseded artifacts.**
   - `ingest-8b73d976c663d7a3` held the 1-ULP-perturbed signature values; it was built before the fix.
   - `ingest-f103b739158ecaa9` had outputs byte-identical to the final artifact and was superseded only by a parse-error message change.
   - Their `data/runs/` execution records are kept.
